## MANDATORY REVIEW CHECKLIST

### 1. Kotlin Style, Explicit API & Type Safety
- **Complete Production Code Only:** NO stubs, placeholder code, `TODO()`, dummy implementations, or `// ... rest of code`.
- **Explicit API Mode (`explicitApi()`):** Every public declaration, return type, and `public companion object` in SDK modules MUST specify explicit visibility modifiers and return types.
- **Single Declaration Per File:** Every primary public `interface`, `class`, or `object` MUST reside in its own dedicated file matching its declaration name. Exceptions apply ONLY to direct subtypes of a `sealed` hierarchy and top-level extension parsers/constants directly bound to a `value class` in the same file.
- **NO Trailing Commas** at the end of argument, parameter, or entry lists.
- **NO Agent-Generated Inline Comments (`//`, `/* ... */`) or New `TODO`/`FIXME`:** Logic must be self-documenting via expressive naming and private helper decomposition. Preserve pre-existing developer `// TODO:` / `// FIXME:` comments unless explicitly resolved by the task. **NEVER delete, strip, or omit KDoc (`/** ... */`).**
- **NO Fully Qualified Names (FQN):** Forbidden in expressions, type annotations, generics, and KDoc links. Use `import` or `import ... as ...` aliases. Permitted ONLY inside `@Deprecated(..., replaceWith = ReplaceWith(...))` import parameters or when technically unavoidable (must be justified).
- **Strict Prohibition of `!!`:** Non-null assertion (`!!`) is strictly forbidden in production code (allowed ONLY in test files). Use `?.`, `?:`, `as?`, smart-casts, or `requireNotNull(...)` / `checkNotNull(...)` with descriptive messages strictly for unrecoverable invariants.
- **Control Flow (`when` & `if`):**
  - NO function or suspend calls inside `when (...)` parentheses and NO `when (val x = someCall())`. Extract the call to a `val` on the preceding line first.
  - Exhaustive `when` on `sealed` types and `enum`s without `else` unless logically unavoidable.
  - Mandatory `{ ... }` block braces for all `if` statements (NO single-line `if (cond) return`; put `return` on its own line inside braces).
- **Naming, Function Bodies & Companion Objects:**
  - Concrete domain-focused outcome variable names (`validationResult`, NOT `result` or `data`). DTO properties use `camelCase` with `@SerialName` referencing `*ApiFields` constants.
  - Simple mappers use expression-body (`=`); multi-step or branching logic uses block-body (`{ ... }`).
  - Place `public companion object` at the bottom of the class body (unless implementing `NavigationScreenParamsParser<P>`); extract constants as `public const val`.
- **Inline Value Classes & Wire `.value`:**
  - `@JvmInline value class` domain IDs/wrappers MUST be `@Serializable`, expose `.value`, `asString()` / `asHexDashString()`, companion `generate()` (when applicable), and `String.toXxxOrNull()` / `String.toXxxOrThrow()` in the same file.
  - Domain enums and extensible interfaces expose `.value` for wire string representation (NEVER `.serialName`).

### 2. Backend Architecture, Dual-Connector, Dagger DI & Persistence
- **Vertical Layering & Packaging (`route`, `usecase`, `manager`, `repository`, `di`, `config`):**
  - **Routing (`BaseRouter`):** Request/response serialization, route mapping, and DTO syntax validation ONLY.
  - **Use Cases (`*UseCase`):** Pure, atomic business operations and domain/business validation (existence, state limits, permissions); return `AppResult.Success` or map failures to `AppError`.
  - **Managers:** High-level domain orchestration across multiple use cases, background tasks, or complex lifecycles.
  - **Repositories:** Direct data access via Exposed (PostgreSQL) or Lettuce (Redis).
  - Declare server path segments in `PathConstants` and custom headers in `HeaderConstants`.
- **Dual-Connector & Server Infrastructure:**
  - Enforce port separation between **Public API** (client/webhook traffic) and **Management API** (internal traffic, `/health/live`, `/health/ready`, metrics).
  - Bootstrap via `KtorServer.create(commonConfig)`; support graceful shutdown (`KTOR_SHUTDOWN_GRACE_PERIOD_MS`, `KTOR_SHUTDOWN_TIMEOUT_MS`, `AppShutdownHookImpl`), `ForwardedHeaders`/`XForwardedHeaders` behind proxies, and `AppInfo` injection.
- **Dagger 2 DI & Configuration:**
  - Every module MUST provide its own explicit Dagger `@Module` (`*Module.kt`) using `javax.inject` (`@Inject`, `@Singleton`, `@Provides`, `@Binds`).
  - Resolve env/properties via dedicated `*ConfigFactory` singletons; declare env keys as `public const val` in `*EnvKeys` objects.
  - Long-running coroutines/listeners MUST execute in a supervised `BackgroundScope` for graceful shutdown.
- **Flyway, Cache Sync & Stateless WebSockets:**
  - All schema changes MUST use Flyway migration scripts under `db/migration/core/<module>/` or `db/migration/feature/<feature>/`.
  - Stateful services MUST synchronize/invalidate local caches via Redis Pub/Sub; WebSocket broadcasts MUST publish over Redis Pub/Sub for multi-replica delivery.

  - Strictly separate `publicArgs` (client-safe localization placeholders) from `secretArgs` (internal diagnostics NEVER exposed to clients).
- **Data Masking:** Sensitive data (PII, credentials, tokens) in logs and audit events MUST be redacted using masking utilities from `core/common`.
- **Centralized Localization (`shared-foundation`):**
  - **NO Local JSON Dictionaries:** NEVER store local JSON translation files (`error_messages.json`, etc.) or hardcoded string dictionaries in `backend-platform-sdk`.
  - Use embedded type-safe `*ModuleStrings` facades (`CommonModuleStrings`, `SecurityModuleStrings`, `UserModuleStrings`, and `emailTemplates` with `LocalizationFormatter.format(template, args)`).
  - Each module implements its own isolated `AppErrorSpecificParser` (`CommonAppErrorSpecificParser`, `SecurityErrorParser`, `UserErrorParser`) handling ONLY its own error codes; `AppErrorParserResolver` delegates sequentially and falls back to `CommonErrorParser`.
